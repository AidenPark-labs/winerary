# Winerary - 서비스 요구사항 정의서

**작성일:** 2026-04-02  
**버전:** v0.1

---

## 1. 서비스 개요

### 1.1 서비스명
**Winerary** (Wine + Diary)

### 1.2 서비스 목적
사용자가 마신 와인을 간편하게 기록하고, 지인과 실시간으로 공유·공동 기록할 수 있는 소셜 와인 다이어리 웹앱

### 1.3 핵심 가치
- **기록의 편의성**: 라벨 촬영 한 번으로 와인 정보 자동 입력
- **공유와 연결**: 함께 마신 사람들과 동시에 같은 기록 작성
- **취향 발견**: 품평 데이터 축적을 통한 나만의 와인 취향 파악

### 3.3 AI 와인 인식 (라벨 촬영)

> **방향**: 외부 와인 DB를 사용하지 않고, 촬영한 라벨 이미지를 AI(멀티모달 LLM)에 직접 전송하여 와인 정보를 추출·추론하는 방식으로 구현한다.

| ID | 기능 | 우선순위 | 설명 |
|---|---|---|---|
| AI-01 | 라벨 이미지 촬영/업로드 | 필수 | 카메라 촬영 또는 갤러리에서 라벨 이미지 선택 |
| AI-02 | 이미지 직접 전송 및 AI 분석 | 필수 | 라벨 이미지를 그대로 AI에 전송, 이미지 내 텍스트·로고·디자인을 종합 분석하여 와인 정보 추론 |
| AI-03 | 와인 정보 구조화 출력 | 필수 | AI가 추출한 결과를 와인명, 빈티지, 생산국, 지역, 품종, 생산자 등 구조화된 형태로 반환 |
| AI-04 | 불확실 항목 표시 | 필수 | AI가 확신하지 못하는 항목은 "추정" 표시 및 사용자에게 직접 입력 유도 |
| AI-05 | 인식 결과 확인 및 수정 | 필수 | AI가 제안한 정보를 사용자가 검토·수정 후 저장 |
| AI-06 | 다중 이미지 지원 | 보류 | 앞면·뒷면 라벨 등 복수 이미지를 함께 전송하여 정확도 향상 (추후 보강) |

**AI 처리 흐름:**
```
라벨 촬영/업로드
    ↓
이미지 → AI (Claude Vision 등 멀티모달 LLM)
    ↓
구조화된 와인 정보 반환
{
  name: "Château Margaux",
  vintage: 2018,
  country: "France",
  region: "Bordeaux / Margaux AOC",
  grapes: ["Cabernet Sauvignon", "Merlot"],
  producer: "Château Margaux",
  type: "Red",
  confidence: { vintage: "high", region: "medium", grapes: "low" }
}
    ↓
사용자 확인 및 수정
    ↓
기록 저장 + 라벨 이미지 보관
```

**AI 프롬프트 설계 방향:**
- 앞면 라벨 이미지 1장만 사용 (다중 이미지는 추후 보강)
- 라벨에서 읽을 수 있는 텍스트를 우선 추출
- 텍스트만으로 부족한 경우 라벨 디자인·로고·색상 등 시각적 단서로 최선을 다해 추정
- 인식 불가 항목은 null 반환 (빈칸으로 두고 사용자가 직접 입력)
- 정확도보다 **빠른 초안 제공**이 목표 — 사용자가 결과를 검토·수정하는 것이 기본 흐름

### 3.4 실시간 공유 및 공동 기록 (핵심 기능)

| ID | 기능 | 우선순위 | 설명 |
|---|---|---|---|
| SHARE-01 | 세션 생성 | 필수 | 공동 기록을 위한 세션(방) 생성 |
| SHARE-02 | 초대 링크 생성 | 필수 | 세션 참여 URL 또는 코드 생성 및 공유 |
| SHARE-03 | 세션 참여 | 필수 | 링크/코드로 세션에 참여 (비회원도 열람 가능) |
| SHARE-04 | 실시간 동시 편집 | 필수 | 여러 참여자가 동시에 같은 와인 기록에 코멘트/품평 추가 |
| SHARE-05 | 참여자 현황 표시 | 필수 | 현재 세션에 접속 중인 참여자 목록 실시간 표시 |
| SHARE-06 | 채팅/반응 | 선택 | 세션 내 간단한 채팅 또는 이모지 반응 |
| SHARE-07 | 세션 기록 저장 | 필수 | 공동 기록된 내용을 개인 다이어리에 저장 |
| SHARE-08 | 공개/비공개 설정 | 필수 | 기록별 공개 범위 설정 (비공개/링크 공유/팔로워/전체 공개) |

### 3.5 품평 (와인 평가)

| ID | 기능 | 우선순위 | 설명 |
|---|---|---|---|
| EVAL-01 | 3축 품평 입력 | 필수 | 아래 3가지 축으로 와인 평가 |
| EVAL-02 | 별점 입력 | 필수 | 0.5점 단위 1~5점 종합 평점 |
| EVAL-03 | 품평 시각화 | 선택 | 레이더 차트 등으로 3축 점수 시각화 |
| EVAL-04 | 공동 품평 집계 | 선택 | 공유 세션에서 참여자 품평 평균 표시 |

**품평 3축 정의:**

| 축 | 항목 | 설명 | 측정 방식 |
|---|---|---|---|
| 1축 | **밸런스 (Balance)** | 산미·탄닌·당도·알코올의 조화 | 1~5점 슬라이더 |
| 2축 | **복잡성 (Complexity)** | 향과 맛의 층위·다양성·여운 | 1~5점 슬라이더 |
| 3축 | **가성비 (Value)** | 가격 대비 만족도 | 1~5점 슬라이더 |

> **비고**: 3축 명칭 및 기준은 사용자 피드백을 통해 조정 가능. 후보 대안: (향/맛/여운), (과실미/구조감/피니쉬) 등

## 4. 비기능 요구사항

### 4.1 성능
- 페이지 초기 로딩: 3초 이내 (LCP 기준)
- AI 라벨 인식 응답: 5초 이내
- 실시간 동시 편집 지연: 500ms 이하

### 4.2 가용성
- 목표 업타임: 99.5% 이상

### 4.3 보안
- 사용자 데이터 암호화 전송 (HTTPS)
- 공유 세션 접근 권한 관리
- 개인정보처리방침 준수 (GDPR, 국내 개인정보보호법)

### 4.4 접근성 및 호환성
- 반응형 웹 (모바일 우선 설계)
- 최신 브라우저 지원 (Chrome, Safari, Firefox, Edge)
- 모바일 카메라 접근 지원 (라벨 촬영)

## 5. 기술 검토 항목

| 영역 | 후보 기술 | 비고 |
|---|---|---|
| 프론트엔드 | React / Next.js | SSR, SEO 고려 |
| 백엔드 | Node.js (Express/Fastify) / Supabase | 실시간 기능 포함 |
| 실시간 동기화 | Supabase Realtime / Socket.io / Liveblocks | 공동 편집 핵심 |
| AI 라벨 인식 | Claude API (claude-opus-4-6 멀티모달) | 라벨 이미지 직접 전송, 외부 DB 미사용 |
| AI 페어링 추천 | Claude API | 자연어 기반 추천 |
| 데이터베이스 | PostgreSQL (via Supabase) | |
| 이미지 스토리지 | Supabase Storage / S3 | 라벨 이미지 보관 (AI 분석 후 원본도 저장) |
| 인증 | Supabase Auth / NextAuth.js | 소셜 로그인 포함 |

## 6. 화면 구성 (주요 페이지)

```
/ (홈/랜딩)
├── /login              로그인/회원가입
├── /diary              내 와인 다이어리 (목록)
│   ├── /diary/new      새 기록 작성 (라벨 촬영 포함)
│   └── /diary/:id      기록 상세 / 수정
├── /session            공유 세션
│   ├── /session/new    세션 생성
│   └── /session/:code  공유 세션 참여 (실시간 공동 기록)
├── /stats              통계 및 취향 분석
└── /profile            프로필 / 설정
```
