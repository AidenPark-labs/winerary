**작성일:** 2026-04-24
**상태:** 방향 합의됨, 세부 확정 전

## 0. 배경과 원칙

### 0.1 진단

슬로건은 **"오늘 먹은 와인을 친구와 같이 기록"**이지만, 현재 UX는 다음 5가지 이유로 "나 혼자 쓰는 와인 일기장"에 가깝다.

1. **하단 탭 5개 중 4개가 "나"의 것.** 친구 진입점이 탭 레벨에 없음.
2. **기록 폼이 ~580줄의 감정가 모드.** 20-30대 여성의 일상 충동 기록과 맞지 않음.
3. **"같이 기록"이 사후 병합.** 각자 혼자 기록 → 수동 연결. 진짜 공동기록이 아님. (*이 문제는 `shared-diary-design.md`에서 "공유 다이어리" 개념으로 이미 해결안 제시됨 — 본 기획서는 그 개념을 탭 구조에 통합.*)
4. **다이어리 첫 화면에 "오늘"이라는 시간 감각이 없음.** 슬로건과 UI가 불일치.
5. **통계·지도·품종 TOP이 "나만 보는 창고".** 공유 가능한 포맷 없음.

### 0.2 설계 원칙

- **Mobile-first.** 모든 와이어프레임은 세로 모바일 기준.
- **핵심 루프는 3탭 안에 완결.** 피드(돌아오는 이유) → 기록(머무는 이유) → 탐색(더 할 것).
- **기록은 가볍게, 상세는 선택적으로.** 빠른 기록 80%, 상세 기록 20% 가정.
- **친구가 먼저 보여야 같이 기록이 발생한다.** 공유 다이어리·결산 카드 모두 "친구 존재감"이 전제.
- **베타는 벤토 기반 + 버건디 악센트 + 크림 서피스로 리디자인.** 레거시 다크 버건디는 그대로 유지(공존). 시각 토큰·컴포넌트 규격은 `docs/design-system.md` 참조.
- **친구는 요청-수락 기반 양방향 관계.** 피드·멘션·공유 다이어리 추천 등 모든 "친구" 스코프는 수락된 관계에 한정.
- **앱 내 결산 카드는 예외적으로 밝은 톤.** 외부 공유 목적(인스타 스토리 등)이라 앱 본체와 톤이 달라도 됨.
- **초대·공유는 "사용자가 직접 카카오톡으로 공유" 우선.** 앱이 알림을 대신 보내는 것(알림톡)보다 사용자 맥락이 붙는 직접 공유가 20-30대 여성 타겟에 더 자연스럽고 바이럴에 유리.

## 1. 정보 구조(IA) 재설계

### 1.1 현재 vs 제안

| 현재 | 제안 (B톤 레이블) |
|---|---|
| 와인노트 (내 기록) | **노트** (홈). 내 기록 + 내가 속한 공유 노트 통합 타임라인. 필터 chips로 보기 전환. |
| 와인검색 | **둘러보기** (찾아보기 + 오늘의 와인 + **친구가 좋아한 한 잔** + 언젠가 마셔볼 + 와인 이야기) |
| 와인추천 | (둘러보기로 통합) |
| 내 와인 | (둘러보기로 통합) |
| 마이페이지 | **나** (프로필 + 나의 와인 이야기 + 결산) |
| — | **중앙 플로팅 "+" 버튼** (가볍게 남기기) |
| ~~함께 (피드)~~ | **제거** (2026-04-24 v2 결정). 앱 thesis가 "같이 마시고 같이 기록"이라 친구의 solo 활동 피드는 메인 탭 자리 정당화 안 됨. 친구 touchpoint는 재배치. |

**3탭 + 중앙 플로팅**:

```
┌──────────────────────────────┐
│                              │
│         (화면 콘텐츠)          │
│                              │
│                              │
│                              │
├──────────────────────────────┤
│  노트      [+]    둘러보기   나 │
└──────────────────────────────┘
```

### 친구 touchpoint 재배치

| 터치포인트 | 이전 위치 | 새 위치 |
|---|---|---|
| 친구 요청 배너/카운트 | 함께 탭 | **노트 홈 헤더 종 아이콘** (배지 카운트) |
| 친구 활동 피드 | 함께 탭 | **제거**. 대신 노트 타임라인에 "○○님도 이 와인 좋아했어요" 힌트 카드 간헐 노출 |
| 친구 solo 기록 발견 | 함께 탭 (전체 피드) | **둘러보기 > 친구가 좋아한 한 잔** 섹션 (큐레이션 카드) |
| 공유 노트 기록 (친구 포함) | 함께 + 노트 (중복) | **노트 탭만** (공유 노트 필터로 접근) |

- 중앙 "+" = 빠른 기록 모달 (모든 탭에서 항상 접근 가능)
- 기록 탭 = "내 다이어리" + "공유 다이어리 N개" 목록 진입점

### 1.2 탭별 역할

| 탭 | 역할 | 첫 화면 구성 |
|---|---|---|
| **노트** (홈) | 내 와인 일기장 — 개인 기록 + 공유 노트 통합 | 상단: 필터 chips (전체 / 내 노트 / 공유 노트 각각). 아래: 시간 섹션(오늘/이번 주/지난달) 통합 타임라인. 헤더 종 아이콘에 친구 요청 배지. |
| **+** (플로팅) | 가볍게 남기기 모달 | 사진 + 마음 점수 + 한 마디 |
| **둘러보기** | 찾아보기·오늘의 와인·친구가 좋아한 한 잔·언젠가 마셔볼·와인 이야기 | 상단 "이 와인, 찾고 있어요?" / 오늘은 이런 와인 / **친구가 좋아한 한 잔** / 언젠가 마셔볼 / 와인 이야기 |
| **나** | 프로필·이야기·결산·설정 | 이번 달 나의 와인 / 결산 카드 / 설정 |

### 1.3 기존 페이지의 재배치

| 현재 경로 | 이동/변경 |
|---|---|
| `/diary` | 피드 탭의 "내 활동" 뷰 + 기록 탭의 "내 다이어리" 로 분화 |
| `/diary/new` | 플로팅 "+" 모달로 진입점 변경, 페이지 자체는 "상세 편집" 화면으로 유지 |
| `/diary/[id]/link`, `/diary/[id]/link-mine` | **제거**. 공유 다이어리로 대체 (`shared-diary-design.md` 준수) |
| `/invite/[code]` | **유지하되 부차적**. 기본 공유는 공유 다이어리 초대 |
| `/find`, `/recommend`, `/wishlist`, `/dictionary` | 탐색 탭 하위 세그먼트로 통합 |
| `/wine-map` | 나 탭 → "내 와인 지도" 서브 페이지로 이동 |
| `/stats` | 이미 `/profile` 리다이렉트 — 유지 |

## 2. 화면별 와이어프레임

### 2.1 피드 탭 (신규)

```
┌─────────────────────────────────┐
│  함께                     🔔 3  │
├─────────────────────────────────┤
│ [내 자리] [친구] [함께 쓰는 노트]│ ← 세그먼트
├─────────────────────────────────┤
│  새로운 인연이 기다리고 있어요 → │ ← 친구 요청 있을 때만
├─────────────────────────────────┤
│                                 │
│  오늘                            │
│  ┌───────────────────────────┐  │
│  │ 지영 · 2시간 전            │  │
│  │ [사진]  샤또 마고 2018     │  │
│  │ ⭐ 4.5  "초콜릿 향이..."   │  │
│  │ 📖 와인 동호회             │  │
│  └───────────────────────────┘  │
│                                 │
│  이번 주                         │
│  ...                            │
│                                 │
│  지영님도 이 와인을 좋아하셨대요 │
│  [바롤로 2019, 기록 보기]        │
└─────────────────────────────────┘
```

- **세그먼트 3개**: `내 자리` · `친구` · `함께 쓰는 노트` — 기본은 "친구" (돌아오는 이유 강조)
- **시간 섹션**: `오늘` / `이번 주` / `지난달`
- **힌트 카드**: "지영님도 이 와인을 좋아하셨대요" — 자연스러운 연결 유도
- **알림 뱃지**: 태그·함께 쓰는 노트 활동

기존 `shared-diary-design.md`의 "다이어리 목록" 구조 유지, 레이블만 B톤으로.

## 3. 핵심 플로우

### 3.1 첫 기록 (가볍게 남기기)

```
[+] 탭 → 사진 선택 → 마음 점수 → 담기
                                    ↓
                    토스트: "오늘의 한 잔, 담아뒀어요.
                             이 와인을 찾고 있어요..."
                                    ↓
                    (백그라운드 와인 찾기 완료 후)
                    알림: "이 와인, 맞나요?
                           샤또 마고 2018인 것 같아요."
                            [맞아요]   [다시 찾아볼게요]
```

**기존 대비**: 7단계 → 3단계. 와인 찾기는 사후 확인으로 이동.

### 3.2 공동 기록 (shared-diary와 연동)

```
피드 탭 → "친구들과 같이 기록하려면?" 힌트 카드
  또는
기록 탭 → [+ 공유 다이어리 만들기]
  ↓
이름 입력 → 커버 이미지 → 초대 링크 생성
  ↓
카톡/문자 공유 → 친구 참여
  ↓
누구나 기록 추가 (빠른 기록 모달에서 "📖 다이어리 선택"으로 저장)
  ↓
각자 독립적으로 평가 (record_participants)
```

기존 `shared-diary-design.md` 플로우 그대로 채택.

### 3.3 친구 피드 둘러보기

```
앱 실행 → 피드 탭 (기본) → [친구] 세그먼트
  ↓
친구가 기록한 와인 카드들 (시간순)
  ↓
카드 탭 → 상세 → "나도 기록할래" 버튼
  ↓
해당 와인으로 빠른 기록 모달 프리필
```

**소셜 루프**: 친구 활동을 보고 → 비슷한 와인을 마시고 싶어지고 → 내가 기록한 걸 친구가 보고.

### 3.4 친구 요청/수락

두 가지 진입 경로:

**A. 앱 내 검색으로 요청**
```
탐색 탭 상단 → [🔍 친구 찾기]
  ↓
닉네임/유저코드 검색 → 프로필 카드 → [친구 요청]
  ↓
메시지 첨부 (선택, 200자): "와인 모임에서 만났던 민지야!"
  ↓
상대에게 웹 푸시 알림 + 앱 뱃지 → [수락 / 거절]
```

**B. 초대 링크 공유로 요청**
```
탐색 탭 → [친구 초대 링크 복사] 또는 [카카오톡으로 공유]
  ↓
사용자가 직접 카카오톡에서 친구에게 링크 전송
  ↓
상대가 링크 진입 → 내 프로필 + 자동 "친구 요청됨" 상태 → [수락]
```

- **멘션 범위**: 수락된 친구만 @ 대상. 기존 `record_mentions` UI는 유지하되 검색 범위 제한.
- **친구 요청 상태**: `pending` / `accepted` / `rejected` / `blocked`. rejected·blocked 후 재요청 쿨다운.
- **메시지 첨부**: A 경로에서 최대 200자. 스팸 억제용 rate limit(시간당 10건 등).
- **공유 다이어리 멤버**: 친구 관계 없이도 참여 가능(초대 링크 기반). 다이어리 멤버 ≠ 친구. 단 공유 다이어리 참여 시 "이 멤버와 친구 되기" 카드 자연 노출.

### 3.5 월간 결산 공유

```
나 탭 → "이번 달 결산 카드" → [공유하기]
  ↓
결산 이미지 생성 → 인스타 스토리/카톡 공유
  ↓
(외부 유저) 링크 진입 → 앱 스토어 → 가입 → 피드 진입
```

**사용자 획득 루프**의 시작점.

### 알림·공유 인프라 (Phase 3·4에 걸쳐 필요)

**두 트랙으로 분리**:

#### 트랙 1: 사용자 주도 공유 (기본)
- **카카오톡 공유 SDK** (Kakao JS SDK, `Kakao.Share.sendDefault`) — 사용자가 직접 친구에게 링크 전송
- **Web Share API** (`navigator.share`) — iOS/Android 네이티브 공유 시트
- **링크 복사** — 모든 기기 공통 fallback
- **적용 대상**: 공유 다이어리 초대, 친구 초대, 결산 카드 공유, 개별 기록 공유
- **장점**: 별도 발송 비용·템플릿 승인 없음. 사용자 맥락(개인 메시지)이 붙어 전환율 ↑.

#### 트랙 2: 시스템 이벤트 알림
- **웹 푸시**: Service Worker + Web Push API. Supabase Edge Function에서 발송. 주 채널.
- **카카오 알림톡** (옵션): 사업자 등록 보유 중, 유저가 별도 진행. 템플릿 승인 후 보조 채널로 투입.
- **발송 대상**: 친구 요청 도착/수락, 내가 멘션됨, 공유 다이어리에 새 기록 추가됨, 내 기록에 친구 평점 추가됨.
- **대체 플랜**: 알림톡 구축이 지연되면 웹 푸시 단일 채널로도 기능 완결.

#### 유저 설정
나 탭 → 알림 설정: 종류별 on/off + 채널별(푸시/알림톡) on/off.

**실 유저 2명 규모** 고려 시 Phase 3 이전엔 알림 없이 인앱 뱃지만으로도 OK. 본 인프라는 Phase 3~4 시점에 맞춰 구축.

**Phase 순서 자체는 추후 재확정 예정.** 제안(2→1→3→4→5)은 초안.

## 7. Voice & Tone

### 7.1 기본 원칙

- **기능어가 아니라 경험어.** "저장", "DB 매칭", "기록" 같은 시스템 어휘를 사용자 대면에 노출하지 않는다.
- **함축과 여백.** 긴 설명보다 짧은 묘사. 한 줄이 부족한 것이 한 줄 넘치는 것보다 낫다.
- **존댓말, 단 거리감 있는 존댓말.** "~하세요"(지시) 지양, "~해보세요" / "~할까요" / 명사 종결("~남기기", "~담기") 선호.
- **은유는 와인에서 빌린다.** 한 잔, 향, 여운, 페어링, 자리, 담다, 남기다, 기울이다.
- **이모지는 절제.** 🍷 정도만 포인트. 😊✨🎉 계열 지양.

### 7.2 두 톤 레지스터

**기본 톤: 브런치 (B)**
- 적용 범위: 앱 본체 전체 — 탭 레이블, 버튼, 빈 상태, 토스트, 에러 메시지, 설정, 플로우 안내
- 성격: 문학적 여백, 짧은 시구. 일상이지만 조용히 아름다운 결.
- 참고 모델: 카카오 브런치, 무인양품 카피, 오늘의 문장

**결산 카드 톤: 인스타 스토리 (C)**
- 적용 범위: 월간·연간 결산 카드, 마일스톤 카드, 외부 공유용 이미지
- 성격: 짧고 리듬감 있는 요즘 말투. 숫자·이모지 활용. 공유하고 싶게 만드는 경쾌함.
- 참고 모델: Spotify Wrapped, Apple Music Replay, 인스타 스토리 스티커

### 7.3 어휘 치환표

| 기능어 (X) | 경험어 (O, B톤) |
|---|---|
| 기록하기 | 한 잔 남기기 / 담아두기 |
| 저장 | 간직하기 / 담기 |
| DB 매칭 / 인식 / OCR | 이 와인 맞나요? / 이 와인인 것 같아요 |
| 검색 | 찾아보기 |
| 와인 사전 | 와인 이야기 |
| 공유 다이어리 | 함께 쓰는 와인 노트 |
| 위시리스트 | 언젠가 마셔볼 와인 |
| 추천 | 오늘은 이런 와인 어때요 |
| 통계 / 분석 | 나의 와인 이야기 / 지나온 한 잔들 |
| 동행자 / 멘션 | 함께한 사람 |
| 빠른 기록 | 가볍게 남기기 |
| 상세 입력 | 더 자세히 남기기 |
| 로그아웃 | 다음에 또 올게요 |
| 편집 | 다듬기 |
| 삭제 | 지우기 |
| 업로드 중 | 담는 중 |
| 네트워크 오류 | 잠시 길이 막혔어요 |
| 아직 기록이 없어요 | 첫 잔의 기억, 여기서 시작돼요 |

### 7.4 문장 패턴

**B톤 — 허용되는 문형**
- 명사 종결: "한 잔의 오늘", "기억하고 싶은 향"
- 완만한 청유: "남겨볼까요", "담아둘까요"
- 묘사형 완료: "오늘도 다녀가셨네요", "새로운 인연이 생겼어요"
- 질문형 여백: "오늘, 어떤 와인이었나요?"

**C톤 — 허용되는 문형**
- 짧은 감탄: "까베르네가 최애!"
- 숫자 강조: "12잔 🍷", "평균 ⭐ 4.1"
- 경쾌한 질문: "올해의 한 잔, 찾으셨나요?"
- 고유명 주어: "민지의 4월"

### 7.5 절대 쓰지 않는 표현

- "데이터", "매칭", "인식", "동기화", "저장 완료", "업데이트됨" — 시스템 내부어 노출
- "~하세요" 강한 지시형 (회원가입·동의 등 법적 필수 외)
- "고객님", "사용자님" — 거리감 과잉
- "완벽", "최고", "강력" — 과장형
- "아래 버튼을 누르세요" — 설명형 UX 지시

### 7.6 상황별 마이크로카피

#### 탭 레이블 (B톤)
- **함께** (기존 "피드") — 친구 중심 사회적 공간
- **노트** (기존 "기록") — 내·공유 다이어리
- **+** (플로팅) — 라벨 없음, 아이콘만
- **둘러보기** (기존 "탐색") — 검색·추천·위시리스트·이야기
- **나** — 그대로

#### 빠른 기록 모달
```
헤더:  "오늘의 한 잔"
사진:  "오늘의 한 컷"
별점:  "마음에 들었나요?"
메모:  "기억해두고 싶은 한 마디"
노트:  "어디에 담을까요? ▼"
액션:  [더 자세히 남기기]   [가볍게 담기]
저장 후 토스트: "오늘의 한 잔, 담아뒀어요"
```

#### 와인 매칭 확인
```
이 와인, 맞나요?
샤또 마고 2018인 것 같아요.
[맞아요]   [다시 찾아볼게요]
```
매칭 실패 시: "잠시 못 찾았어요. 조금 더 알려주실래요?"

#### 피드 빈 상태
```
첫 잔의 기억, 여기서 시작돼요.
사진 한 장으로 오늘을 남겨보세요 →
```

#### 친구 없음 상태
```
곧 함께 기울일 친구가 생기겠죠.
[친구 초대 링크 보내기]
```

#### 친구 요청 도착
```
새로운 인연이 생겼어요.
지영님이 친구가 되고 싶어해요.
"와인 모임에서 만났던 지영이에요"
[수락]   [나중에]
```

#### 공유 다이어리 초대
```
와인 동호회에 초대받았어요.
함께 쓰는 와인 노트, 시작해볼까요?
[참여하기]   [나중에]
```

#### 에러·네트워크
- 일반 오류: "잠시 길이 막혔어요. 다시 시도해볼까요?"
- 업로드 실패: "사진이 잘 담기지 않았어요"
- 로그인 실패: "잠깐 문이 닫혔어요. 다시 열어주세요"

#### 성공 토스트
- 기록 저장: "오늘의 한 잔, 담아뒀어요"
- 친구 수락: "{이름}님과 함께하게 됐어요"
- 공유 다이어리 생성: "새 와인 노트가 시작됐어요"
- 결산 카드 공유: "오늘의 이야기를 나눴어요"

### 7.7 적용 우선순위

Phase별 마이크로카피 리라이팅 순서:
1. **Phase 1 (빠른 기록)**: 모달·토스트·매칭 확인 — 7.6 최우선 적용
2. **Phase 2 (탭 재구성)**: 탭 레이블·빈 상태 — 탭 명칭 한 번만 확정
3. **Phase 3 (공유 다이어리)**: 초대·참여·삭제 예정 안내
4. **Phase 4 (친구 피드)**: 친구 요청·수락·시간 섹션
5. **Phase 5 (결산 카드)**: C톤으로 전면 작성

Phase마다 디자이너 또는 유저가 문구 최종 검수.

## 8. 공존 전략 (구·신 버전 병행)

레거시를 그대로 둔 채 신규 UX를 **같은 앱 `/beta/*` 경로로 추가**. UX 테스트 기간 동안 유저가 양쪽을 왕복할 수 있고, 와인 기록이 연속으로 보이도록 설계.

### 8.1 아키텍처 선택

| 옵션 | 판정 |
|---|---|
| **(채택) 같은 앱 `/beta/*` 라우트** | DB·인증 자동 공유, 한 배포, 왕복 용이 |
| 모노레포 별도 Next 앱 | 인증/배포 이중화, 실유저 2명 규모엔 과잉 |
| 서브도메인(`beta.winerary.app`) | 쿠키 도메인·CORS 문제, 스케일 대비 과잉 |

### 8.2 데이터 공유 매트릭스

| 테이블 | 전략 | 비고 |
|---|---|---|
| `wines`, `raw_wines` | 공유 (읽기/쓰기) | 와인 카탈로그 단일 소스 |
| `wine_records` | 공유 + 새 컬럼(NULLABLE) 추가 | 양쪽에서 연속된 내 기록 표시 |
| `profiles` | 공유 | 같은 Supabase 인증 |
| `friends`, `friend_requests` (신규) | 공유 DB에 신규 테이블 | 레거시 미조회 |
| `shared_diaries`, `shared_diary_members`, `record_participants` (신규) | 공유 DB에 신규 테이블 | 레거시 미조회 |
| `wine_records.diary_id`, `created_by` (신규 컬럼) | NULLABLE로 추가 | 레거시 무시 |

### 8.3 쓰기 규칙

- **베타가 `wine_records`에 쓸 때**: 기존 컬럼 의미 불변. 신규 개념은 새 컬럼/테이블에만.
- **공유 다이어리 기록**: `wine_records`에 저장, `diary_id` 세팅. 레거시에서 안 보이거나(다른 유저 기록) 평범한 기록처럼 표시되고 깨지진 않음.
- **레거시가 쓴 기록**: 베타에서 `diary_id IS NULL`인 개인 기록으로 자연 표시.
- **모든 스키마 변경은 additive.** 컬럼 rename·type 변경·non-null 추가 금지.

### 8.4 코드 구조

```
src/
  app/
    (app)/              ← 레거시 (건드리지 않음)
      diary/ find/ recommend/ wishlist/ profile/ ...
    beta/               ← 신규 v1
      layout.tsx        ← 베타 전용 BottomNav, 테마
      page.tsx          ← "함께" 탭
      notes/            ← "노트" 탭
      explore/          ← "둘러보기" 탭
      me/               ← "나" 탭
      record/new/       ← 가볍게 남기기 모달
    api/                ← 공용. 베타 전용 엔드포인트는 /api/beta/*
  components/
    legacy/             ← 레거시 전용
    beta/               ← 베타 전용
    shared/             ← 공용 (Button, Avatar, 기본 WineCard 등)
  lib/
    supabase/           ← 공용
    db/
      queries.ts        ← 공용
      beta-queries.ts   ← 베타 전용 (friends, shared diary 등)
```

- `components/shared/`는 **읽기 전용 계약**. 한쪽 요구로 변경해 다른 쪽이 깨지면 안 됨. 변화가 필요하면 prop 추가만 허용, 기존 인터페이스 보존.
- 다른 쪽에서 다르게 보이게 해야 할 땐 `components/beta/` 또는 `components/legacy/`에 **별도 변형**을 만든다.

### 8.5 진입점 (토글)

- 레거시 → 베타: `/profile` 하단에 "베타 버전 체험하기 →" 링크 → `/beta`
- 베타 → 레거시: 베타 "나" 탭에 "기존 버전으로 돌아가기 →" 링크 → `/diary`
- 쿠키·세션·DB 공유이므로 같은 브라우저에서 왕복 자유.

### 8.6 롤백 계획

베타 폐기 시:
1. `src/app/beta/`, `components/beta/`, `lib/db/beta-queries.ts` 디렉토리 삭제
2. `/profile`의 베타 진입 링크 제거
3. 신규 테이블(`friends`, `shared_diaries` 등) `DROP`
4. `wine_records.diary_id` 등 신규 컬럼 `DROP`
5. 레거시는 변경 없음

### 8.7 주의사항

- **RLS 정책**: 신규 테이블은 "멤버만" 기본. 레거시가 우연히 호출해도 안전.
- **`components/shared/` 오염 방지**: 공용 컴포넌트 변경 시 반드시 양쪽 사용처 점검.
- **URL 혼동 허용**: 유저가 베타 브라우저에서 `/diary`를 열면 레거시가 뜸. 사고 아닌 의도된 동작.
- **베타 노출 게이트**: 실유저 2명 규모엔 전면 공개 OK. 규모가 커지면 `profiles.beta_enrolled` 플래그 도입.
